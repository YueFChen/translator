    # 翻译插件：当前实现

翻译插件在桌面端处理多语言 CSV。它以自己的 manifest、契约、Vite UI 和 stdio 后端独立打包；Core 只从动态插件入口加载 Activity，并按能力代理文件、模型网络和密钥服务。构建入口是 `pnpm build`，产物为 `target/translator-plugin`。当前是开发阶段，数据库结构不做旧版兼容迁移；`project.sqlite` 的 schema 版本为 8。界面在 `ui/src/Workspace.tsx`，Rust 业务代码在 `src/`，host service 适配在 `src/main.rs`。

## Workspace 入口与能力

清单只注册一个主 Activity（`main`），并选择 `theme.followHost`；Core 管理 Activity 的入口与生命周期，插件 UI 直接填充 Workspace 内容区。后端能力为 `files.pick`、`files.export`、`network.model` 和 `secrets.plugin`：CSV 通过 Core picker 的短期句柄读取，模型请求和密钥服务经 Core 代理。长任务通过 `job.progress` / `job.log` 汇报，请求取消由协议 request ID 关联。

本插件数据库和输入快照写入 `%APPDATA%\com.wonderland.assistant\plugin-data\translator\`。原数据库、输入快照与密钥密文是开发样本，不会迁移到新目录；API Key 则由 Core 的插件隔离密钥服务保管。

插件的定位是**全自动**：作业、翻译记忆与词库都不设人工审批闸门，唯一的例外是界面上对单条记忆/词条执行"禁用"——这是数据安全阀，不是放行流程。

## 工作区与数据流

1. 选择 UTF-8 CSV（可带 BOM），检查表头并设置列映射。前三列依次是“来源”“是否需要翻译”“简体中文”；目标语言列按文件实际内容选择，不要求 17 列。输入复制为只读哈希快照，原文件不改。
2. 预检生成独立的工作记录。同一 CSV 可以有多次工作记录，每次模型运行是该记录下的任务。左侧记录树可收起，记录可重命名。选中记录看原表，选中任务看该任务已完成译文叠加后的表。没有自建分组。
3. 主区域以表格为中心，CSV、词库、翻译记忆分别成表；表格容器内滚动并分页，表头冻结。API 管理与任务参数在浮层抽屉中，新增和编辑 API 使用相对应用居中的弹窗。
4. 默认仅处理标记为 `TRUE`、源文非空、所选目标语言单元格为空的格。任务参数可勾选“同时翻译标记为 `FALSE` 的行”；该选择随任务保存，续跑及该任务草稿导出沿用它，其他标记值仍不处理。已有译文保留。翻译记忆**不设审批**：只要该条启用、格式校验通过，且同一作用域键下只有一种译法，就直接复用；同一键出现多种译法时无法机械择一，交回模型。词库同样不设“已审核”开关，启用即参与：整格精确命中的词条直接填格，句内命中作为模型约束——普通词给译名，**不可译词（如品牌名）作为"保持原文"清单进提示词**，否则"欢迎来到 Wonderland"这类句子里的品牌名会被译掉。预检另会标出**疑似被上游切分的拼接片段**（以没有对应开标签的结束标签开头、以未闭合的开始标签结尾、以连接标点开头、去除变量与标签后无文本），只作提示，既不阻止导出也不改变派发；判定只看单元格自身，不推断相邻格属于哪一句。
5. 模型任务按工作记录及任务 ID 持久化，可暂停、续跑、取消。续跑核对工作记录和输入快照，并使用当前激活的 API；失败格、上次进程遗留在 `running` 的格、以及取消时未结算的格都会被退回待处理，由作业自己重发——不引入人工核对，代价是可能重复计费。作业因内部错误提前退出时会被收口成"失败"（未结算的格一并记为失败），库里遗留的 `running` 会在界面读状态前收成"已暂停"：任务不会卡在"运行中既暂停不了、又看不出问题"的状态。**模型服务整体不可用**（连接失败、持续 5xx/429、超时）不是"这些格失败了"，而是"现在翻不了"：整批退回待处理、作业停在"已暂停"并说明原因，服务恢复后点"继续"接着跑——一次网络抖动不该把一批好数据记成失败，更不该逼用户重新发起。
6. 正式导出只含原有内容与记忆/词条复用结果；所选任务的草稿导出额外读取该任务成功且格式安全的译文。两个出口均保持输入表头、列顺序及数据列，输出 UTF-8 BOM CSV。变量、富文本和必译格仍为空等校验信息留在内部，不增加报告列或附加表头。
7. 运行期间界面显示**进度条与运行日志**。进度事件按 1 秒节流后发出（作业结束时必发一次）；日志按批推送若干行：作业参数、**每个片段模型返回的译文**、逐格失败原因、每批成功/失败数与结算格数、预算触顶、暂停/取消与最终汇总。解析失败时日志会带上模型的原始返回（截断到 400 字符）——这是排查"模型到底说了什么"的唯一线索。译文超过 500 字符只在日志里截断显示，完整内容以表格与草稿导出为准。

## 作业状态机

`jobs.status` 的过程态只有 `queued` / `running`，终态为 `succeeded` / `failed` / `cancelled`；`paused` 是可以继续的中间态。

| 状态 | 何时出现 | 界面可做 |
| --- | --- | --- |
| `queued` | 作业已建行、调度器还没接手（进程恰好在此刻退出） | 继续 |
| `running` | 调度器正在派发 | 暂停、取消 |
| `paused` | 用户暂停、预算触顶、模型服务整体不可用、或启动时发现遗留的 `running` | 继续 |
| `succeeded` | 全部格已结算且无失败 | 导出 |
| `failed` | 有格失败，或调度自身出错被收口 | 继续（重排失败格） |
| `cancelled` | 用户取消 | 继续（重排未结算的格） |

四条不变式与它们的落点：

1. **"运行中"必须真的在跑**。只有持有作业控制块的进程才算在跑，因此界面读任务状态前会把库里遗留的 `running` 收成 `paused`（`pause_orphan_running`）——否则界面显示运行中、点暂停却只会得到"当前没有进行中的翻译作业"。
2. **每次退出都有终态**。正常结束按格汇总；调度自身出错（数据库错误、子任务 panic）由 `settle_after_error` 把作业与未结算的格一起记为 `failed`。子任务 panic 时它的格留在 `running`，作业收尾会因此判为"仍有待处理格"并停在 `paused`，而不是冒充成功。
3. **未结算的格永远不丢**。`queued`/`running` 由续跑退回待处理，`failed` 由续跑重排；因此取消与失败都不是死路，唯一不可续的状态是 `succeeded`。
4. **同一进程同时只有一个作业**（`busy` 闸门），作业行与作业控制块在"建行 → 派发"之间不留可被误判的窗口。

`job_units.status` 更简单：`queued → running → succeeded | failed`；`running → queued` 只出现在"取了批但被暂停/取消（请求没发出去）"、"批次按提示词长度复核后装不下而退回尾部片段"和"续跑回收上次遗留的运行中格"三处，三处都会把 `attempt` 退回去。

## API 与凭据

API 列表可保存多个配置。卡片左侧显示用户填写的模型显示名称及实际调用的模型 ID，中间显示基础地址与备注，右侧提供使用、编辑、删除。配置还包含 OpenAI 兼容基础地址、Key、回环端点权限、超时、速率与单价等字段。只有激活的配置用于新任务；初始状态没有自动创建的空配置。Key 通过 Core `core.secrets.plugin.*` 服务存储在 `%APPDATA%\com.wonderland.assistant\plugin-secrets\translator\provider-{id}.dpapi`，列表只返回 `has_key`。模型请求经 Core `core.network.model`，由 Core 校验端点、禁止重定向并限制响应大小。

首个适配器使用 OpenAI 兼容的 Chat Completions 接口。模型输出必须是按片段序号回填的 JSON（`translations[].id` 与提示词里的编号一一对应），并通过占位符与富文本校验。提示词分四层注入：**硬规则**（占位符逐字保留、花括号/尖括号内部不译不改大小写、数字/版本号/路径/URL 照抄、不加解释不漏译、纯占位片段原样返回、译文里的引号与换行按 JSON 转义）、**术语译名**、**保持原文的不可译词**、**少量既有译文示例**，最后才是带序号的源文片段。提示词超长时按"示例 → 不可译词 → 术语译名"的顺序反向截断，源文永不截断。调度按并发、每分钟请求数、超时和预算控制；服务端 429 遵循 `Retry-After`。批次层面同理：装不下只会少装几条，**绝不裁开一条源文**。

任务创建时保存单价和货币，历史费用按该快照与实际 token 用量计算，切换当前 API 不会重算旧任务。任务最终状态按单元格结果汇总：存在失败为“失败”，全部成功才标为“已完成”。这些状态与校验结论只留在工作区；导出目录仅发布翻译 CSV。

当前模型请求以**批次**为单位：一批里装若干去重组（源文、语境、资源键、目标语言与占位签名都相同的格合成一个组，共用一次调用）。同批只装源语言与目标语言相同的组，默认每批 16 个片段，可在任务参数里调整，上限 32。批次大小按**片段数与字符数综合判定**，不按固定行数：单批源文预算 = 提示词上限 − 2000 字符（预留给指令模板、术语约束与示例，免得源文刚好顶满、再加指令就必然超限）；粗筛之后还会用**真实渲染出的提示词长度**复核一次，装不下的尾部片段原样退回待处理。收缩的粒度是整条片段——一条超长记录宁可独占一批，也不把源文截成半句。

提示词把片段按 1 起编号列出，响应必须按 `translations[].id` 回填；缺条目的片段单独记为失败，不牵连同批其余片段，其余结果照常落库。错误按类分三路：**结果不确定**与**响应不可用**（缺字段、错语言、无效 JSON）按退避重试，最多两次，用尽后把该批记为失败；**模型服务整体不可用**（连接失败、持续 5xx/429、超时）用尽重试也不记失败，而是整批退回待处理、作业停在可续跑的"已暂停"；**配置无效**（端点、模型名、密钥）重试无解，作业直接记为失败。不保留待人工核对的中间态。

批次键与预检的 `unique_units` 是同一套哈希，预检报多少唯一片段就是本次要翻的片段总数；跨任务与语境不同的文本仍分别付费。每次请求重复携带固定指令、匹配术语和目标语言最多 5 条既有译文示例。`job_usage.requests` 按真实发出的网络调用累计（失败与重试都计入，一次批量调用算一次）；token 和费用仅依赖成功响应的 `usage` 字段，服务不返回时只计请求数。因此界面请求数是完整口径，费用仍取决于服务返回值。

## 存储与边界

- 输入快照：`%APPDATA%\com.wonderland.assistant\plugin-data\translator\inputs\{sha256}.csv`。工作记录、任务、词库、记忆与非密钥 API 配置：同目录 `project.sqlite`。
- 导出经 Core `files.export` 写到“文档\Wonderland Assistant\translator\Exports”，先写临时产物，重新解析后发布；不覆盖输入原件。
- CSV 最大 128 MiB，单格最大 1 MiB，最多 200,000 条记录、32 个目标列和 1,000,000 个唯一待填任务。
- 富文本标记规则应与 `../rich_editor/ui/src/markup.ts` 对齐。变量（例如 `{A.B}`）检查身份和次数，可随语言调整顺序。
- 目前仅有 OpenAI 兼容适配器；其他 API 格式、中间语言模式、领域语料自动提炼尚未实现。没有独立 QA 页面或 QA 报告导出。
